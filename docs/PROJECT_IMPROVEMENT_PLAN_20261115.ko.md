## 1. 보완 방향

기존 점검에서 발견한 주요 실행 문제는 수정되었다. 다음 단계에서는 작은 코드 정리보다 개선 효과의 재현성, 최고 성능 모델의 저장·추론, 오류 분석을 우선한다.

권장 작업 순서는 여러 시드 비교, 최고 모델 저장·추론, OOF 기반 오류 분석이다. README의 설명 수정은 작업량이 작으므로 먼저 반영할 수 있다.

## 2. 여러 시드에서 개선 효과 확인

**우선순위: 최우선**

현재 최고 OOF ROC-AUC 0.74052는 시드 42 하나에서 얻은 결과이다. 기존 실험의 모든 변형을 반복하기보다 다음 네 가지를 선정해 3~5개 분할 시드에서 비교한다.

| 비교 대상 | 목적 |
|---|---|
| 베이스라인 | 고정된 비교 기준을 확보한다. |
| 튜닝한 LightGBM | 튜닝 효과가 분할 변경에도 유지되는지 확인한다. |
| CatBoost | 다른 모델 계열의 성능을 확인한다. |
| LightGBM·CatBoost 결합 | 결합 효과가 분할 변경에도 유지되는지 확인한다. |

각 시드에서는 동일한 행과 fold를 사용해 모델 간 차이를 짝지어 비교한다. 입력 전처리와 튜닝 예산 등 비교 조건을 기록하고, 튜닝은 해당 외부 학습 fold 내부에서 수행한다.

분할 시드와 모델·튜닝 시드를 구분해 기록한다. 우선 분할 시드만 바꾸면 데이터 분할에 대한 민감도를 살펴볼 수 있고, 모델·튜닝 시드까지 바꾸면 그 변동도 함께 포함된다.

기록할 항목은 다음과 같다.

- 시드별 pooled OOF AUC와 AP
- 같은 시드에서 베이스라인 대비 개선 폭
- 시드별 실행 시간
- 전체 시드의 평균, 표준편차 및 범위
- 데이터·소스 해시, 사용 설정 및 패키지 버전

**해석 한계:** 반복 분할은 같은 데이터를 재사용한다. 여러 시드에서도 개선이 유지되는지는 확인할 수 있지만, 반복 결과를 독립 표본으로 간주하거나 새로운 독립 테스트를 대신했다고 주장하지 않는다.

## 3. 최고 성능 모델의 저장·추론 경로 완성

**우선순위: 높음**

현재 [`predict_test.py`](../predict_test.py)는 고정 베이스라인으로 학습하고 제출 파일을 생성한다. 최고 성능 결합 모델에도 전처리·모델·설정을 저장하고 다시 불러와 예측하는 경로를 추가한다.

| 구성 요소 | 보완 내용 |
|---|---|
| 학습 | 최종 설정을 선택하는 절차와 전체 학습 데이터 또는 fold 모델의 사용 방식을 명시한다. |
| 저장 | 학습된 전처리, 모델, 특성 목록·자료형, 하이퍼파라미터 및 결합 규칙을 함께 보관한다. |
| 추론 | 저장된 구성 요소를 불러와 새로운 입력에 동일한 처리를 적용한다. |
| 입력 검증 | 누락·추가 열, 자료형 불일치, 알 수 없는 범주 등의 처리 규칙을 확인한다. |
| 검증 | 저장 전후의 동일 입력 예측이 허용 오차 내에서 일치하는지 확인한다. |
| 기록 | 모델 파일 해시, 소스·데이터 해시 및 패키지 버전을 남긴다. |

### 순위 평균의 출력 의미

현재 결합 실험은 모델별 예측의 순위를 평균한다. 이 값은 임신 확률이 아니라 상대적인 예측 점수이다.

- 출력 명칭과 문서에서 점수와 확률을 구분한다.
- 테스트 전체 배치에서 순위를 계산하는지 등 결합 규칙을 명시한다.
- 배치 구성에 따라 순위 점수가 달라질 수 있음을 설명한다.
- 단일 행 예측을 지원하려면 해당 상황에 적용할 점수 변환 방식을 별도로 정의하고 검증한다.

확률이 필요하다면 확률 보정 절차와 별도의 검증을 설계한다. 순위 점수를 그대로 임신 확률로 표시하지 않는다.

## 4. OOF 기반 오류 분석 추가

**우선순위: 높음**

전체 AUC만으로는 어떤 집단에서 개선되고 어디에서 실패하는지 설명하기 어렵다. 기존 OOF 예측을 활용해 주요 집단별 성능을 분석한다.

| 분석 축 | 확인할 내용 |
|---|---|
| 시술 유형: IVF·DI | 규모와 양성 비율이 다른 집단에서 성능과 개선 방향이 어떻게 달라지는지 확인한다. |
| 시술 당시 나이 | 나이대별 오류와 개선 폭을 확인한다. |
| 난자 출처 | 본인 난자·기증 난자 등 입력 집단에 따른 차이를 확인한다. |

집단별로 행 수, 양성 수, 양성 비율, AUC 및 AP를 기록한다. 동일한 행에서 베이스라인과 개선 모델을 비교한다. 한 클래스만 있는 집단에서는 AUC를 계산하지 않고, 표본이 작은 집단의 값은 불안정할 수 있음을 함께 표시한다. AP는 양성 비율의 영향을 받으므로 서로 다른 집단의 수치를 단순 비교하지 않는다.

### 입력의 사용 가능 시점 확인

이식된 배아 수나 배아 이식 경과일처럼 시술이 진행된 뒤에 알 수 있는 입력이 있다. 모델을 어느 시점에 사용하는지 정의하고, 각 특성이 그때 이용 가능한지 정리한다.

현재 대회 입력을 모두 사용하는 모델과 시술 전 예측을 목적으로 하는 모델을 동일한 설정으로 해석하지 않는다. 환자·병원 단위 일반화는 확인된 그룹 식별 정보가 있어야 평가할 수 있다.

특성 중요도를 추가할 경우에는 예측에 기여한 관계와 인과관계를 구분한다.

## 5. CI에서 개선 실험의 연결 경로 검증

**우선순위: 중간**

현재 테스트는 전처리, 손실 함수, 옵션 검증 등 개별 동작을 확인한다. 여기에 합성 데이터로 개선 실험의 주요 연결 경로를 짧게 실행하는 테스트를 추가한다.

검증할 경로는 다음과 같다.

1. 작은 합성 데이터로 내부 튜닝을 수행한다.
2. LightGBM과 CatBoost를 학습한다.
3. 각 모델의 OOF 예측을 생성하고 결합한다.
4. 예측 파일과 요약 보고서를 저장한다.
5. 저장된 결과의 행 정렬, 유한한 점수, 메타데이터 및 요약 지표를 확인한다.

튜닝 횟수와 학습 규모는 작게 제한한다. 이 테스트의 목적은 성능 수치 재현이 아니라 개별 함수 사이의 연결 오류를 검출하는 것이다. 대회 원본 데이터는 CI에서 사용하지 않는다.

관련 파일: [`improve_cv.py`](../improve_cv.py), [`missing_types_cv.py`](../missing_types_cv.py), [`tests/`](../tests/), [GitHub Actions 설정](../.github/workflows/tests.yml)

## 6. README의 학습·테스트 분포 설명 보완

**우선순위: 즉시 반영 가능**

위치: [`README.ko.md`](../README.ko.md) 8-5의 학습·테스트 구분 모델 설명 및 [`README.md`](../README.md)의 대응 문장

앞선 점검에서 놓친 설명이 있다. 현재 문장은 학습 행과 테스트 행을 구분하는 분류기가 둘을 구분하지 못하면 분포가 비슷하고 테스트 성능도 유지될 가능성이 높아진다고 설명한다.

그러나 구분하지 못했다는 결과만으로 분포의 동일성이나 예측 성능 유지를 보장할 수 없다. 구분 모델의 표현력과 검증 설계에 따라 차이를 탐지하지 못할 수 있으며, 입력과 타깃 사이의 관계 변화는 테스트 정답 없이 확인할 수 없다.

**권장 표현:**

> 학습 행과 테스트 행을 구분하는 분류기를 사용하면 관측된 입력에서 탐지 가능한 분포 차이를 점검할 수 있다. 다만 구분 성능이 무작위 수준이라고 해서 두 분포가 같거나 테스트 예측 성능이 유지된다고 결론낼 수는 없다. 타깃과 입력의 관계 변화 및 실제 테스트 성능은 이 검사만으로 확인하지 못한다.

한국어·영어 README에 같은 범위의 설명을 반영한다.
