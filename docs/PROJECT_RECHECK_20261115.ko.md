## 1. 종합 판단

기존 주요 문제는 수정되었다. 캐시 생성 조건을 비교하는 로직, 실험 변형의 실행 순서 정규화, GAIN 최종 추론의 평가 모드 적용이 추가되었다. README의 GAIN 효과 및 결측치 해석도 기존 지적을 대부분 반영한다.

자동 테스트 39개가 모두 통과하고, 5,000행 베이스라인의 AUC·AP·F1은 기존 결과와 정확히 일치한다. 순서를 바꿔 전달한 실험 옵션도 학습과 앙상블까지 정상 완료한다.

다만 캐시 백업 이름의 충돌, 캐시 변경 감지 대상의 누락, 문서에 남은 이전 표현 등 세 가지 보완점이 있다. 현재 환경의 의존성 누락으로 캐시의 실제 전체 생성·재사용 경로는 끝까지 검증하지 못한다.

| 최초 지적 | 반영 상태 |

## 4. 추가 보완 사항

### 4.1. 캐시 백업이 덮어써질 수 있다

위치: [`build_cache.py`](../build_cache.py)의 `_set_aside()` — 점검 당시 100~104행 부근

백업 이름은 다음처럼 초 단위 시각으로 만들어진다.

```text
<name>.stale-YYYYMMDDTHHMMSS.npz
```

같은 초에 동일한 이름의 캐시를 두 번 백업하면 목적지 경로가 같아진다. 현재 macOS 환경에서는 `Path.rename()`이 기존 목적지 파일을 덮어쓴다.

임시 파일과 고정된 시각으로 두 번 백업한 결과, 백업 파일은 하나만 남고 첫 번째 파일의 내용이 사라지는 것을 재현한다. 따라서 기존 캐시를 보존한다는 의도와 어긋난다.

**권장 조치:** 마이크로초나 UUID 등으로 고유한 이름을 만들고, 기존 백업 파일을 덮어쓰지 않도록 처리한다. 연속 백업 시 두 파일이 모두 보존되는 회귀 테스트를 추가한다.

### 4.2. 캐시 변경 감지에서 `src/config.py`가 빠져 있다

위치: [`build_cache.py`](../build_cache.py)의 `SOURCES` — 점검 당시 57~59행 부근

캐시 생성 과정은 [`src/config.py`](../src/config.py)의 `get_device()`와 `set_seed()`를 사용하지만, 해당 파일은 해시 대상 목록에 포함되지 않는다.

임시 복사본에서 장치 선택 코드를 바꿔도 `cache_spec()`이 반환한 서명이 동일함을 확인한다. 이 경우 관련 동작을 수정해도 기존 캐시가 유효한 것으로 판단될 수 있다.

**권장 조치:** `src/config.py`를 `SOURCES`에 추가한다. 해당 파일을 변경했을 때 캐시 서명이 달라지는지도 검증한다.

### 4.3. 문서에 이전 표현이 일부 남아 있다

#### 과거 캐시를 “현재 코드로 재생성”했다고 설명한다

위치: [`README.ko.md`](../README.ko.md) 109행 부근 및 [`README.md`](../README.md)의 같은 재측정 설명

과거 캐시를 여전히 “현재 코드로 재생성”했다고 설명한다. 하지만 이번 수정으로 GAIN 최종 대체에 `G.eval()`이 적용되어, 과거 캐시를 생성한 구현과 현재 구현이 달라졌다.

[`docs/RESULTS.md`](RESULTS.md)에도 `rebuilt by the current build_cache.py`라는 표현이 남아 있다. 뒤에서 구현 변경과 미재실행 사실을 설명하지만, 앞 문장부터 시점을 명확히 하는 편이 일관된다.

**권장 표현:** “2026-11-14 당시 코드로 재생성한 캐시”로 수정한다.

#### 결측 여부 열 처리에 여전히 “버그 수정”이라는 표현을 사용한다

위치: [`docs/experiments/MISSING_TYPES.md`](experiments/MISSING_TYPES.md) 결과 표 — 점검 당시 54행 부근

```text
median_flags0: only the type 4 bug fixed
```

공식 데이터 정의서를 확인하지 못했으므로, 빈칸의 의미를 확정한 버그 수정으로 부르기보다는 실험에서 적용한 처리를 기술하는 편이 정확하다.

**권장 표현:** “여부 열의 빈칸을 0으로 처리” 또는 `treat flag blanks as 0`로 통일한다.

## 5. 실행 환경의 남은 한계

현재 점검 환경에는 `xgboost`, `imbalanced-learn`, `skorch`가 여전히 설치되어 있지 않다. PyTorch는 2.15.0으로, 구형 요구사항의 고정 버전인 2.2.1과 다르다.

실제 캐시 생성 시도에서는 다음 오류가 발생한다.

```text
ModuleNotFoundError: No module named 'seaborn'
```

오류는 `src.feature_selection` import 과정에서 발생한다. `seaborn`은 [`requirements.txt`](../requirements.txt)에 명시되어 있으므로, 이 결과는 현재 환경의 설치 누락과 구분해 해석해야 한다.

따라서 자동 테스트와 GAIN 단독 추론 검증은 통과했지만, 실제 전처리부터 GAIN 캐시 생성·재사용까지의 전체 경로가 정상이라고 확정하지는 않는다. 구형 워크플로의 전체 의존성을 별도 환경에 설치한 후 추가 확인이 필요하다.
