## 1. 종합 판단

기존의 주요 문제는 수정되었다. 캐시 생성 조건 비교 로직, 실험 변형의 실행 순서 정규화, GAIN 최종 추론의 평가 모드 적용이 추가되었으며, README의 GAIN 효과 및 결측치 해석에도 기존 지적이 대부분 반영되었다.

자동 테스트 39개가 모두 통과하였고, 5,000행 베이스라인의 AUC·AP·F1은 기존 결과와 정확히 일치하였다. 순서를 바꿔 전달한 실험 옵션도 학습과 앙상블까지 정상적으로 완료되었다.

다만 캐시 백업 이름 충돌, 캐시 변경 감지 대상 누락, 문서에 남은 이전 표현 등 세 가지 보완점이 있다. 또한 현재 환경의 의존성 누락으로 캐시의 실제 생성·재사용 전체 경로는 끝까지 검증하지 못하였다.

## 4. 추가 보완 사항

### 4.1. 캐시 백업 파일의 덮어쓰기 가능성

위치: [`build_cache.py`](../legacy/build_cache.py)의 `_set_aside()` (점검 당시 100\~104행 부근)

백업 파일 이름은 아래와 같이 초 단위 시각으로 생성된다.

```text
<name>.stale-YYYYMMDDTHHMMSS.npz
```

같은 초에 동일한 이름의 캐시를 두 번 백업하면 목적지 경로가 같아진다. 현재 macOS 환경에서는 `Path.rename()`이 기존 목적지 파일을 덮어쓴다.

임시 파일과 고정된 시각으로 두 번 백업한 결과, 백업 파일이 하나만 남고 첫 번째 파일의 내용이 사라지는 것을 재현하였다. 이는 기존 캐시를 보존한다는 의도와 어긋난다.

**권장 조치:** 마이크로초나 UUID 등으로 고유한 이름을 생성하고 기존 백업 파일을 덮어쓰지 않도록 처리. 연속 백업 시 두 파일이 모두 보존되는지 확인하는 회귀 테스트 추가

### 4.2. 캐시 변경 감지 대상에서 `src/config.py` 누락

위치: [`build_cache.py`](../legacy/build_cache.py)의 `SOURCES` (점검 당시 57\~59행 부근)

캐시 생성 과정은 [`src/config.py`](../legacy/src/config.py)의 `get_device()`와 `set_seed()`를 사용하지만, 해당 파일은 해시 대상 목록에 포함되어 있지 않다.

임시 복사본에서 장치 선택 코드를 변경해도 `cache_spec()`이 반환하는 서명이 동일함을 확인하였다. 따라서 관련 동작을 수정해도 기존 캐시가 유효한 것으로 판단될 수 있다.

**권장 조치:** `src/config.py`를 `SOURCES`에 추가하고, 해당 파일 변경 시 캐시 서명이 달라지는지 검증

과거 캐시를 여전히 "현재 코드로 재생성"했다고 설명한다. 그러나 이번 수정으로 GAIN 최종 대체에 `G.eval()`이 적용되어, 과거 캐시를 생성한 구현과 현재 구현이 달라졌다.

**권장 표현:** "2026-11-14 당시 코드로 재생성한 캐시"로 수정

## 5. 실행 환경의 남은 한계

현재 점검 환경에는 `xgboost`, `imbalanced-learn`, `skorch`가 여전히 설치되어 있지 않다. PyTorch 버전도 2.15.0으로, 구형 요구사항의 고정 버전인 2.2.1과 다르다.

실제 캐시 생성 시도에서는 아래 오류가 발생하였다.

```text
ModuleNotFoundError: No module named 'seaborn'
```

이 오류는 `src.feature_selection` import 과정에서 발생한다. `seaborn`은 [`requirements.txt`](../legacy/requirements.txt)에 명시되어 있으므로, 이 결과는 현재 환경의 설치 누락으로 구분해 해석해야 한다.

따라서 자동 테스트와 GAIN 단독 추론 검증은 통과하였으나, 실제 전처리부터 GAIN 캐시 생성·재사용까지의 전체 경로가 정상이라고 확정하지는 않는다. 구형 워크플로의 전체 의존성을 별도 환경에 설치한 후 추가 확인이 필요하다.
